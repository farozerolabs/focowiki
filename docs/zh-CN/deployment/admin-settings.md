# Admin 配置

在 Admin UI 的知识库页面打开**设置**。保存后的值会在服务重启后继续保留。修改会应用到新请求和新启动的任务；已经运行的任务可能继续使用启动时的值直至完成。

以下内容与当前设置页实际显示的字段一致。建议从默认值开始，确认 CPU、内存、PostgreSQL、所选搜索服务和 S3 延迟后再提高并发。

## API 限流

| 设置 | 用途 | 默认值 |
| --- | --- | --- |
| 管理员登录 / 最大请求数 | 一个窗口内允许的登录尝试次数。 | `8` |
| 管理员登录 / 窗口秒数 | 登录计数窗口长度。 | `900` |
| Admin API / 最大请求数 | 一个窗口内允许的 Admin UI API 请求次数。 | `600` |
| Admin API / 窗口秒数 | Admin API 计数窗口长度。 | `60` |
| Developer OpenAPI / 最大请求数 | 一个窗口内允许的 Developer OpenAPI 请求次数。 | `1200` |
| Developer OpenAPI / 窗口秒数 | Developer OpenAPI 计数窗口长度。 | `60` |

这些限制在 Focowiki 内生效。反向代理或边缘服务应配置相互匹配的限流规则。

**维护索引**只用于为已有知识库建立首个语义契约、接入修改后的模型、prompt、schema、向量维度或搜索服务，以及执行明确的修复、恢复或完整重建；自动维护不会自动接入这些变更。知识库已有当前语义契约后，普通上传和正文替换会在正常文件处理流程中自动执行 GraphRAG、语义协调、向量生成、受影响图与生成内容更新和最终搜索入库。重命名、移动、元数据更新和删除只更新受影响范围，不需要运行**维护索引**。维护期间，已经可以读取的文件继续可用。状态区域会展示进度、重试、最近活动和需要处理的失败；运行中的维护操作也可以在同一区域取消。

当前语义提取契约只随 [Docker Compose 部署](./docker-compose.md#更新现有部署)所述的干净破坏式存储基线提供。旧版本知识库和内容不会迁移到本版本，也不能在本版本中对其执行维护索引；需要把来源 Markdown 重新导入空目标部署。**维护索引**仅用于当前基线内创建但没有语义契约的知识库，以及后续当前基线内的模型、契约、维度、搜索服务、修复、恢复或完整重建操作。

## 搜索

两种搜索服务继续使用相同的设置字段；修改 `SEARCH_PROVIDER` 不会增加、删除或重命名字段。

| 设置 | Meilisearch 中的作用 | OpenSearch 中的作用 | 默认值 |
| --- | --- | --- | --- |
| 搜索请求超时毫秒 | 限制完整应用搜索请求。 | 限制完整应用搜索请求。 | `3000` |
| 搜索服务超时毫秒 | 原生搜索 cutoff 和客户端 deadline。 | 搜索服务请求/query deadline 和应用 cutoff。 | `1000` |
| 结果补取倍数 | 数据补全前额外获取候选结果。 | 数据补全前额外获取折叠后的候选结果。 | `3` |
| 索引更新文档数 | 单个索引任务的最大文档数。 | 单个 Bulk 请求的最大文档数。 | `10000` |
| 索引更新压缩字节数 | 单个序列化索引批次的最大字节数。 | 单个序列化 Bulk 请求的最大字节数。 | `8388608` |
| 在途搜索任务数 | 并发等待中的索引任务数。 | 并发 Bulk 或搜索服务操作数。 | `8` |
| 搜索任务轮询间隔毫秒 | 两次任务状态检查之间的延迟。 | 重试或最终可见性检查之间的延迟。 | `500` |
| 搜索任务超时毫秒 | 索引任务的总 deadline。 | Bulk、索引和可见性操作的总 deadline。 | `600000` |
| 搜索任务最大尝试次数 | 任务和请求的最大重试次数。 | 临时请求和单项失败的最大重试次数。 | `5` |
| 搜索重试延迟毫秒 | 任务或请求重试前的延迟。 | 临时重试前的延迟，包含小范围随机调整。 | `2000` |
| 搜索清理批次大小 | 持久化旧索引清理的领取批次。 | 持久化精确索引清理的领取批次。 | `1000` |
| 未完成索引保留小时数 | 失败或被替换候选索引的保留时间。 | 失败或被替换候选索引的保留时间。 | `24` |
| 搜索结果摘要长度 | 原生 crop 长度。 | 高亮片段和标准化摘要的最大长度。 | `1200` |

搜索服务超时必须低于总请求超时。所选搜索服务的内存或磁盘延迟上升时，降低单次更新大小或在途任务数。

## 语义搜索

OpenSearch 和 Meilisearch 共用相同的语义设置。这些字段限制可选的实体、关系、社区和向量增强，不会修改生成文件树或来源 Markdown。

| 设置 | 用途 | 默认值 |
| --- | --- | --- |
| 最大分块字符数 | 单个提取分块的最大字符数。 | `8000` |
| 最大分块数 | 单个来源 revision 的最大提取分块数。 | `32` |
| 最大证据目标数 | 单个语义单元保留的来源证据目标上限。 | `64` |
| 最大社区分区数 | 单次操作处理的社区分区上限。 | `256` |
| 最大社区实体数 | 单个社区分区组装的实体上限。 | `10000` |
| 最大社区关系数 | 单个社区分区组装的内部关系上限。 | `20000` |
| 最大社区边界关系数 | 单个社区分区组装的边界关系上限。 | `10000` |
| 最大社区摘要字符数 | 单个社区摘要保留的字符上限。 | `8000` |
| 社区适配器超时毫秒 | 单个社区分析请求的最长时间。 | `30000` |
| 语义搜索通道截止毫秒 | 可选语义搜索通道的独立截止时间，不能高于完整搜索请求超时。 | `2500` |
| 查询向量并发 | 单进程同时执行的查询向量请求上限。 | `4` |
| 查询向量缓存条目数 | 单进程查询向量缓存条目上限。 | `1000` |

建议从默认值开始。来源处理 Worker 的 CPU 或内存、模型延迟或搜索延迟升高时，降低分块、社区或查询向量限制。可选语义通道失败时会返回安全的语义状态，已经完成的精确和词法通道仍可返回结果。

对于已有语义契约的知识库，现有文件处理列表会依次展示 GraphRAG 处理、语义协调、向量生成、受影响图与生成内容更新和搜索入库。搜索入库是最后一个必需的索引门禁；该阶段成功前，文件不会显示为已就绪或可见。没有语义契约的知识库仍可使用基础文件优先流程，并会显示需要维护语义索引，不会只把后续上传文件写入不完整的语义语料。

## 向量模型

向量模型在独立的设置页签中管理，并同时适用于两种搜索服务。云服务使用带认证的 HTTPS endpoint；认证模式 `none` 仅用于可信本地或私有网络 endpoint。

| 设置 | 用途 | 默认值或初始值 |
| --- | --- | --- |
| 显示名称 | Admin UI 中显示的名称。 | 包含服务商和用途。 |
| 认证模式 | `api_key` 发送后端凭据；`none` 不发送凭据。 | `api_key` |
| Base URL | OpenAI 兼容向量 API 地址。 | `https://api.openai.com/v1` |
| API key | `api_key` 模式使用的后端凭据。 | `api_key` 模式必填，保存后不再完整显示。 |
| 模型名称 | 服务商的向量模型标识。 | 与服务商文档完全一致。 |
| 请求维度 | 兼容服务商支持的可选输出维度。 | 留空时使用模型实际返回的维度。 |
| 归一化 | Focowiki 应用的向量归一化方式。 | `l2`，也支持 `none`。 |
| 最大输入 tokens | 单个向量输入声明的最大预算。 | `8192` |
| 批次大小 | 单次请求发送的向量输入上限。 | `32` |
| 超时毫秒 | 单次向量请求的最长时间。 | `30000` |
| 重试次数 | 服务商临时失败后的最大重试次数。 | `2` |
| 最小请求间隔毫秒 | 两次服务商请求之间的最小间隔。 | `0` |
| 并发 | 同时执行的向量请求上限。 | `4` |
| 最大响应字节数 | 允许接收的服务商响应大小上限。 | `8388608` |

先创建配置，使用**测试**验证 endpoint 和实际向量维度，再使用**启用**。新的语义任务会固定使用一个准确的生效配置 revision。编辑已保存配置会创建新 revision；已有知识库只有在**维护索引**完成后才会接入该 revision。只切换搜索服务时，可以复用兼容的不可变向量产物，无需重复调用相同模型。

表格以只读状态展示实际维度、校验状态和生命周期状态。暂停后，新任务不会再选择该配置；恢复后，暂停的 revision 可以再次被选择。配置 revision 仍被生效或运行中任务引用时不能删除。列表、状态、错误、日志和 API 响应始终隐藏完整凭据。

## Reranker 模型

重排是可选的查询阶段。设置中的 Reranker 页签只保存模型连接、凭据、模型标识、校验、生命周期、超时、重试、最小请求间隔和并发。创建配置后先使用**测试**，再使用**启用**。暂停、替换或删除 Reranker 不会重建知识库，也不会修改语义 generation。Reranker 缺失、暂停或失败时，搜索仍使用确定性的混合排序。

请填写服务商 Base URL，例如 `https://provider.example/v1`。Focowiki 会自动补全 `/rerank`，并向 `https://provider.example/v1/rerank` 发送标准 rerank 请求。该字段不要填写 `/rerank` 或 `/v1/chat/completions`；Reranker 不支持 Chat Completions 协议。

最终结果 `limit`、`rerankTopK` 和 `rerankScoreThreshold` 属于 Developer OpenAPI 单次请求字段，因此不会出现在 Admin 设置中。`rerank` 默认是 `false`；启用后，接口只发送已经授权的标题、路径和限制长度的来源正文摘要。向量 cosine 相关性阈值仍由生效的向量查询策略管理，与 Reranker 分数阈值彼此独立。

## 模型

基础文件优先流程可以不使用生成模型。没有生效模型时，文件上传、导航、精确与词法搜索、确定性关系仍会继续。语义增强需要同时存在生效的生成模型和已校验生效的向量模型配置。同一时间只能有一个生效生成模型。

| 设置 | 用途 | 推荐值 |
| --- | --- | --- |
| 显示名称 | Admin UI 中显示的名称。 | 包含服务商和用途。 |
| API 模式 | 服务商使用的协议。 | `responses` 或 `chat_completions`，与服务商一致。 |
| Base URL | OpenAI 兼容 API 地址。 | 服务商要求时包含 `/v1`。 |
| API key | 后端使用的服务商凭据。 | 使用独立 key 并定期轮换。 |
| 模型名称 | 服务商模型标识。 | 与服务商文档完全一致。 |
| 上下文窗口 tokens | 模型上下文容量。 | 使用服务商公布的上限。 |
| 请求最大超时毫秒 | 单次模型请求允许的总时间。 | 长文件使用 `600000` 或更高。 |
| 请求空闲超时毫秒 | 模型响应没有活动时允许的最长等待时间。 | `120000` 到 `300000`。 |
| 建议生成并发 | 同时执行的模型请求数。 | 从 `1` 或 `2` 开始。 |
| 临时错误重试延迟毫秒 | 服务商临时失败后再次尝试前的等待时间。 | `60000` |
| 请求最小间隔毫秒 | 两次模型请求之间的最小等待时间。 | 稳定服务使用 `0`，严格限流时适当增加。 |

模型创建后不会再次显示完整 API key。暂停模型后，新任务不会再选择该模型。运行中的任务仍在使用模型时，需要等待任务完成后再删除。

## 配置生效

Admin 配置由 Focowiki 保存，不应写入 `.env`。端口、域名、基础设施凭据、数据库连接上限、存储凭据和日志路径仍属于启动配置。修改启动配置后需要重启对应服务。
